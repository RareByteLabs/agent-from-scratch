The idea in one minute

An agent is a language model running in a loop with tools. You describe each tool (a name, a plain-English description and a JSON schema for its inputs). The model replies with either an answer or a request to use a tool. Your code runs the tool, sends the result back, and asks again. The loop ends when the model answers instead of asking for another tool.

That is all the "magic". The rest of this guide is the engineering around it that separates a demo from something you could run for a customer: configuration, secrets, limits on cost and loops, logging, linting, tests, and honesty about what the agent gets wrong.

What we build

An evidence assistant. You ask a medical-evidence question. The agent searches PubMed through the public NCBI API, reads the abstracts, and answers with PMID citations. Then we put a small web page on it, with live progress, a model picker, and token and cost readouts, so a non-technical person can try it.

Before you start

  • A Mac or Linux machine with a terminal, and uv installed (it manages Python and packages).
  • VS Code, or any editor.
  • An Anthropic API key. Before you create one, make a Console Workspace with a small monthly spend limit and create the key inside it (see chapter 8).
  • Git.

1. Create the project

Run this from the folder that will contain your project, not from inside it.

terminal
cd ~/dev
uv init --package --python 3.12 agent1
cd agent1
git branch -m main
git config --global init.defaultBranch main

uv init creates pyproject.toml, src/agent1/__init__.py, a README.md, and hidden .python-version and .gitignore files (use ls -a to see dotfiles). It also runs git init for you, which is why git says master until you rename the branch.

Why the src/ layout
The code you ship lives in one folder. Tests and scripts then import the installed package instead of picking up stray files from the repo root. It is the standard layout for Python applications.
Why pin the Python version
.python-version is what uv runs; requires-python in pyproject.toml is what the project promises. Pinning one version means every machine and CI job runs the same interpreter.

2. Environment and lockfile

terminal
uv sync
uv run agent1

uv sync creates .venv (the project's private copy of Python and its libraries) and uv.lock. Seeing Hello from agent1! proves the install, the entry point and the pinned Python all work.

  • .venv is disposable and gitignored. Delete it any time and uv sync rebuilds it.
  • uv.lock records the exact version and hash of every dependency. It is generated, never hand-edited, and committed for applications so every machine installs identical packages.
Gotcha: the prompt says Python 3.9
Your shell prompt only shows whichever python comes first on PATH, which can be the system one. Check what the project really uses with uv run python --version.

Secrets

  • .env holds the real key and is never committed.

  • In production and CI there is no .env: the same variable comes from real environment variables or a secrets manager. The code only reads the environment, so it doesn't care which source supplied it.

.venv versus .env
.venv is the folder of installed libraries; nothing reads configuration from it and it can be wiped at any time. .env is a small config file python-dotenv reads. Similar names, completely different jobs.

4. The first call to Claude

Three small files in src/agent1/. Each has one job.

src/agent1/config.py
"""Settings come from the environment, loaded in one place, failing fast."""
import os
from dataclasses import dataclass

from dotenv import load_dotenv

load_dotenv()


@dataclass(frozen=True)
class Settings:
    api_key: str
    model: str


def load_settings() -> Settings:
    api_key = os.environ.get("ANTHROPIC_API_KEY")
    if not api_key:
        raise RuntimeError("ANTHROPIC_API_KEY is not set. Copy .env.example to .env and fill it in.")
    return Settings(api_key=api_key, model=os.environ.get("AGENT1_MODEL", "claude-haiku-4-5-20251001"))
src/agent1/llm.py
"""Thin wrapper around the Anthropic SDK. Everything else calls this, never the SDK directly."""
import anthropic
from anthropic.types import Message, MessageParam, ToolParam

from agent1.config import Settings


def complete(
    settings: Settings,
    *,
    system: str,
    messages: list[MessageParam],
    tools: list[ToolParam],
    max_tokens: int = 1500,
) -> Message:
    client = anthropic.Anthropic(api_key=settings.api_key)
    return client.messages.create(
        model=settings.model,
        max_tokens=max_tokens,
        system=system,
        messages=messages,
        tools=tools,
    )
  • config.py: the model name is configuration, not code. A missing key fails immediately with a clear message.
  • llm.py: the only file that touches the SDK, so swapping providers or adding retries later is a one-file change. It always sets max_tokens.
  • cli.py: the entry point. In pyproject.toml the script line is agent1 = "agent1.cli:main".

Run it with a trivial question and check that you get an answer and a token count. That proves the key, the network, the SDK and the plumbing.

Gotcha: import cannot be resolved
If the editor says from agent1.config import Settings cannot be resolved, first run the program. If uv run agent1 works, the code is fine and the editor is looking at the wrong Python. Select ./.venv/bin/python as the interpreter and make sure the files sit in src/agent1/, not the project root.

5. The first tool

src/agent1/tools.py holds two things: the function that does the work, and the description of it that the model reads.

the contract
def search_pubmed(query: str, max_results: int = 5) -> str:
    """Search PubMed, return the abstracts as plain text (capped at 8,000 characters)."""
  1. esearch (NCBI E-utilities) turns the query into a list of PMIDs.
  2. efetch turns those PMIDs into abstracts as text.
  3. The text is capped so one result cannot flood the conversation, and the request has a timeout.

The tool schema is a dictionary with a name, a description and a JSON input_schema (here query required, max_results optional). Treat the description as a prompt: it is how the model decides when and how to use the tool.

Test the tool on its own, with no AI involved:

terminal
uv run python -c "from agent1.tools import search_pubmed; print(search_pubmed('colorectal cancer screening', 2)[:1500])"
Principle
Test each part separately before wiring them together. When the loop misbehaves later you already know the tool works.
Never trust the model's arguments
The schema says what you want; the model can still send something else. Enforce limits in code, for example max_results = max(1, min(max_results, 10)).

6. The agent loop

This is the heart of the project. The simplified version below shows the whole idea; the repository version adds logging, token totals, events and a result object.

agent.py (core)
def run_agent(settings: Settings, question: str) -> str:
    messages: list[MessageParam] = [{"role": "user", "content": question}]

    for step in range(1, MAX_STEPS + 1):
        response = complete(settings, system=SYSTEM_PROMPT, messages=messages, tools=TOOLS)

        if response.stop_reason != "tool_use":          # the model is done
            return "".join(b.text for b in response.content if b.type == "text")

        messages.append({"role": "assistant", "content": response.content})
        results: list[ToolResultBlockParam] = []
        for block in response.content:                  # there may be several tool calls
            if block.type == "tool_use":
                output = run_tool(block.name, block.input)
                results.append({"type": "tool_result", "tool_use_id": block.id, "content": output})
        messages.append({"role": "user", "content": results})

    return "Stopped: step limit reached without a final answer."
  • MAX_STEPS = 6 is a hard stop. A loop with no cap is a bill waiting to happen.
  • Parallel tool calls: one response can contain several tool_use blocks. The loop handles every one, and each tool_result is linked back by tool_use_id.
  • The model is stateless: you resend the full history every step, so prompts grow with each round.
  • run_tool is a deliberate boundary: if a tool crashes, the error goes back to the model as text instead of killing the run. That is the one place a broad except Exception is justified. It carries # noqa: BLE001 - deliberate and log.exception(...), so nothing is hidden from you.

The system prompt tells the model to search PubMed first, cite PMIDs, say plainly when the evidence is weak, mixed or missing, and not rely on memory.

First real run

For "Does screening colonoscopy reduce colorectal cancer mortality?" the log looked like this: step 1 asked for one search; step 2 asked for two searches in a single response (parallel tool use); step 3 ended with a cited answer. About 15,100 tokens in and 600 out, roughly two US cents on a Haiku-class model.

Put the lint configuration in the project so every machine and CI job behaves the same:

uv run ruff format .

uv run ruff check . --fix     # auto-fix what it can
Rule setCatches

Where is this rule coming from?
Ruff reads config from the project, then parent folders, then a personal file (~/.config/ruff/ruff.toml). A pyproject.toml without a [tool.ruff] section is skipped. See which file is active with uv run ruff check --show-settings src/agent1/agent.py | head -20.
Gotcha: a stray import
Accepting an editor autocomplete can slip something like from urllib import response into the top of a file. Ruff flags it as a redefinition. Delete the line, and glance at your import block after accepting suggestions.

Types that mean something

Use the SDK's own types (MessageParam, ToolParam, ToolResultBlockParam) instead of vague list[dict]. Editors complain about a plain list because they cannot prove its contents match what the SDK expects. A list is fine where an iterable is expected; the mismatch is about what is inside it. Annotate the tool schema as SEARCH_PUBMED_SCHEMA: ToolParam = {...}.

Always run commands from the project root (the folder with pyproject.toml): ruff check . means "the current folder", so from src/ it would miss everything else.

8. Cost and guardrails

Agents spend money in loops, so build the brakes before you need them. There are five layers:

LayerScopeWhat it does
MAX_STEPSper runStops the loop after N model calls.
Tool output cap and argument clampper callLimits how much text one tool result can add to the conversation.
MAX_PROMPT_TOKENSper requestStops if a single request's prompt exceeds a budget (we use 60,000).
Cost logper runPrints tokens and estimated dollars at the end of every run.
Console spend limitper monthThe real backstop, set in the Anthropic Console.

Prices are data, not code

Prices change, so they live in one dated, sourced file that is committed to git. A price change then becomes a one-line diff you can review.

src/agent1/prices.toml
# USD per million tokens (list prices; no caching or batch discounts).
# Source: https://platform.claude.com/docs/en/about-claude/pricing
# Last checked: 2026-10-19 (verify before relying on these)
# Not modeled: Haiku 5.5 charges more for prompts over 100K tokens.

[claude-haiku-4-5-20251001]
label = "Claude Haiku 4.5"
input = 1.0
output = 5.0

[claude-haiku-5-5]
label = "Claude Haiku 5.5"
input = 0.10
output = 0.50

[claude-sonnet-5-5]
label = "Claude Sonnet 5.5"

src/agent1/pricing.py
"""Model catalogue and estimated cost. The data lives in prices.toml, not in code."""
import tomllib
from pathlib import Path

_MODELS = tomllib.loads(Path(__file__).with_name("prices.toml").read_text())


def cost_usd(model: str, tokens_in: int, tokens_out: int) -> float | None:
    """Return the estimated cost in USD, or None if the model has no price entry."""
    price = _MODELS.get(model)
    if price is None:
        return None
    return (tokens_in * price["input"] + tokens_out * price["output"]) / 1_000_000


def list_models() -> list[dict[str, str]]:
    """Models the interface may offer: [{"id": ..., "label": ...}, ...]."""
    return [{"id": model_id, "label": entry["label"]} for model_id, entry in _MODELS.items()]
Why not .env for prices?
.env is for secrets and per-machine settings. It is gitignored, so prices there would not be reviewed, versioned or shared with teammates and CI. Rule of thumb: secret or different per machine goes in .env; non-secret and the same everywhere goes in a committed data file; behaviour goes in code.

The 100K-token threshold

Some models charge more once a single request's prompt passes a size (for Haiku 5.5, 100K tokens). It is per request, not the run's total. Because every step resends the whole history, the prompt grows each round. The guard checks the size of the request just sent:

inside the loop
MAX_PROMPT_TOKENS = 60_000  # stay well below the 100K price threshold

if response.usage.input_tokens > MAX_PROMPT_TOKENS:
    log.warning("prompt size %d is over budget, stopping", response.usage.input_tokens)
    return finish("Stopped: prompt budget exceeded.", step, stopped_early=True)

Spend limits in the Console

Limits are set per organization and per Workspace, not per individual key, and the Default Workspace cannot have one. Create a Workspace such as agent1-dev, create the key inside it, and cap it at a small monthly amount. Hitting a limit you set returns HTTP 400; hitting your tier's cap returns 429 enforced_spend_limit_reached. Rate limits (requests or tokens per minute) are a separate setting.

The cost shown by the agent is an estimate at list prices. The Console usage page is the billing truth.

9. A web interface

A thin web layer on top of the same agent, so a non-technical person can use it in a browser. We use FastAPI.

terminal
uv add fastapi "uvicorn[standard]"
mkdir src/agent1/static

First, run_agent returns a structured result instead of a string, so the command line and the web page share one agent and differ only in presentation:

agent.py
@dataclass(frozen=True)
class AgentResult:
    answer: str
    model: str
    tokens_in: int
    tokens_out: int
    cost_usd: float | None
    steps: int
    stopped_early: bool = False
EndpointPurpose
GET /Serves the page, static/index.html.
GET /api/configModel list for the dropdown (built from prices.toml), default model, whether an access code is needed.
POST /api/askRuns the agent and streams progress (next chapter).

The page itself is one self-contained HTML file with no frameworks: src/agent1/static/index.html in this repository.

Habits that keep it safe

  • Re-validate on the server. The model dropdown value is checked against an allow-list. Never trust the browser.
  • Cap the input. Questions are limited to 1,000 characters.
  • Require an access code (AGENT1_ACCESS_CODE in .env). Every request spends your API money.
  • Clean errors. An API failure returns a short message, never a stack trace. Details go to the server log.
  • Treat model output as untrusted text. The page escapes it before displaying it.
  • Make claims checkable. Every PMID in the answer links to PubMed.
  • Plain def endpoints, not async: FastAPI runs them in worker threads, so the blocking agent call does not freeze the server.
run the server
uv run uvicorn agent1.server:app --host 127.0.0.1 --port 8000

Listening on 127.0.0.1 means only this machine can reach it. That is the safe default; chapter 11 covers sharing.

10. Live progress

A real answer takes 10 to 30 seconds. Instead of a spinner, the page shows what the agent is doing: Understanding your question, Searching PubMed for "…", Found 5 references, Reviewing the results…

The agent loop takes an optional callback and reports plain events. It knows nothing about the web:

EventWhenFields
thinkingBefore each model callstep
tool_startBefore a tool runsname, input (the search query)
tool_endAfter a tool returnsname, pmids found
doneRun finishedresult (an AgentResult)
errorSomething faileddetail
agent.py (excerpt)
def run_agent(settings, question, on_event: EventCallback | None = None) -> AgentResult:
    def emit(event):
        if on_event is not None:
            on_event(event)
    ...
    emit({"type": "thinking", "step": step})
    ...
    emit({"type": "tool_start", "name": block.name, "input": block.input})
    output = run_tool(block.name, block.input)
    emit({"type": "tool_end", "name": block.name, "pmids": extract_pmids(output)})

The server runs the agent in a worker thread, puts each event on a queue.Queue, and streams them to the browser as newline-delimited JSON (one JSON object per line):

server.py (excerpt)
def event_stream(req: AskRequest) -> Iterator[str]:
    events: queue.Queue[dict[str, object] | None] = queue.Queue()

    def worker() -> None:
        try:
            result = run_agent(replace(settings, model=req.model), req.question, on_event=events.put)
            events.put({"type": "done", "result": asdict(result)})
        except anthropic.APIError:
            log.exception("Anthropic API call failed")
            events.put({"type": "error", "detail": "The model service returned an error."})
        except Exception:  # noqa: BLE001 - boundary: report any failure to the client
            log.exception("Agent run failed")
            events.put({"type": "error", "detail": "Something went wrong on the server."})
        finally:
            events.put(None)  # sentinel: the stream is over

    threading.Thread(target=worker, daemon=True).start()
    while (event := events.get()) is not None:
        yield json.dumps(event) + "\n"


@app.post("/api/ask")
def ask(req: AskRequest, x_access_code: Annotated[str | None, Header()] = None) -> StreamingResponse:
    check_access(x_access_code)          # checks run BEFORE streaming starts,
    if req.model not in ALLOWED_MODELS:  # so they remain proper HTTP errors
        raise HTTPException(status_code=422, detail="Unknown model.")
    return StreamingResponse(
        event_stream(req),
        media_type="application/x-ndjson",
        headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"},
    )
Why this design
The agent only calls a function, so it stays testable and reusable. The wording of each step lives in the page, which is presentation. Streaming over a normal POST needs no extra library, and the page can still send a request body. Server-Sent Events are GET-only; WebSockets are two-way and overkill here.
A step the page cannot announce
The last step cannot be labelled “Writing the answer” in advance. The model only reveals it is finished when it stops asking for tools, so the page can only say “Reviewing the results”.

Two ways to let someone else try it. The server listens only on your machine, so neither is automatic.

tailscale funnel status         # should show (Funnel on) and a proxy to 127.0.0.1:8000

It works for me but not for my phone
A device logged in to your own tailnet reaches the address privately, even if the public side is not live. Test like your visitor would: a phone on mobile data with Wi-Fi off. If tailscale funnel status says No serve config, nothing is being shared: start it again with --bg. The first time, public DNS can take several minutes. Check with dig +short @8.8.8.8 your-machine.your-tailnet.ts.net.

Before you send anyone a link

  • The access code is set in .env and the server was restarted afterwards.
  • The key lives in a Console Workspace with a small monthly limit. This is your real protection if the link spreads.
  • Tell people not to type patient-identifying information. Questions go to a third-party API.
  • Run their likely questions yourself first (next chapter).

12. Fluent is not the same as correct

The first real answer looked excellent and was wrong in several ways. The same PMID was cited for two different papers. A guideline year looked off. A head-to-head trial (colonoscopy versus a stool test) was cited as if it showed benefit versus no screening. And the answer said "yes, about 50% or more" without mentioning that the main randomized trial of screening colonoscopy (NordICC, 2022) found a smaller effect on cancer incidence and no clear mortality benefit in the intention-to-treat analysis. The system prompt had said to flag mixed evidence. The agent did not.

Lesson
Agents fail quietly. A cited, confident answer is not evidence that it is right. Verify citations against the source, and build evaluation before you trust the output.

What to do next

  1. Tighten the system prompt. Require the answer to separate randomized-trial evidence from observational evidence and to state when they disagree.
  2. Build a small known-answer test set (10 to 20 questions where you know the correct answer and the key papers). Run it after every change to the prompt or model and compare.
  3. Add pytest tests for the parts that are deterministic: tool parsing, the cost function, the event stream, the prompt-budget guard.
  4. Compare models on the same set before choosing. A cheaper model is not automatically as good at multi-step work.
  5. Add CI: run ruff and pytest on every push.

Note on copy and paste: terminal text can lose spaces at line wraps (for example "inLancet"). That is clipboard noise, not a bug in your code.

Questions & answers

The doubts that came up while building this, answered. Use the box to filter.

What does uv add --dev do, and what are pytest, ruff and httpx?
--dev puts a package in a separate dependency group: tools for building the project, not running it. Production installs skip them with uv sync --no-dev. pytest is the test runner (uv run pytest). ruff is the linter and formatter (uv run ruff check, uv run ruff format). httpx is an HTTP client, how our code calls PubMed's web API; the anthropic SDK only talks to Claude.
Why aren't secrets stored in .venv, which is already gitignored?
.venv is the folder of installed libraries. It is disposable and can be rebuilt from uv.lock at any time, so anything stored there would be wiped, and nothing reads configuration from it. .env is a config file at the project root that python-dotenv loads at startup. Git ignores it, so the secret stays local.
If .env is not committed, how does the key get to other machines?
Not through git. .env.example (committed) lists which variables exist. Each environment gets its own real value through a secure channel: a copy of .env on a dev machine (key kept in a password manager, or issue a new one in the Console), real environment variables or a secrets manager in production and CI (GitHub Actions secrets, cloud secret stores, Docker or Kubernetes secrets). Use a separate key per environment, rotate immediately if one leaks, and cap spend.
Why use VS Code and not Claude Code?
It is not either/or. VS Code is the workbench: editor, file tree, terminal. Claude Code is an AI agent that writes and edits code from a terminal. For a first agent, type and read the code yourself so you learn what an agent is made of. Once you can read it, hand routine work (tests, refactors, explanations) to a coding agent and review its diffs. Reviewing AI-written code requires being able to read it.
Why does git say master when I haven't run git init?
uv init ran git init for you (skip that with --vcs none). The branch name comes from git's init.defaultBranch setting, unset by default, so git falls back to master. Fix with git branch -m main for this repo and git config --global init.defaultBranch main for future ones.
Where do I run uv init: inside the folder or outside?
Outside, in the parent folder: uv init --package --python 3.12 agent1 creates the folder. Running it inside an existing empty folder also works, with no name at the end; it names the project after the folder.
What Python version should I give uv init?
Pick one and pin it. --python 3.12 writes .python-version (what uv runs) and requires-python in pyproject.toml (what the project promises). Every machine and CI job then uses the same interpreter.
My prompt shows Python 3.9. How do I fix it?
The prompt shows whichever python is first on PATH, here the macOS system one. uv init does not create the virtual environment and nothing had activated one. Run uv sync, then activate it (source .venv/bin/activate) or let VS Code activate it via the selected interpreter. uv run python --version is the source of truth; the prompt is cosmetic.
What is the extra file uv.lock?
pyproject.toml says what you want (version ranges); uv.lock records exactly what you got, so every machine installs identical packages. Commit it.
Do I run commands from the project root or from src/?
Always from the project root, the folder with pyproject.toml. uv and git search upward so they often still work from src/, but . means the current folder, so ruff check . from src/ checks only src/.
In llm.py, how do the arguments of def complete get passed?
complete(settings, *, system, messages, tools, max_tokens=1500): settings is positional. The bare * makes everything after it keyword-only, so callers must write system=..., messages=..., which prevents mixing up arguments of similar shape. max_tokens=1500 is a default. Inside, the values are forwarded by keyword to client.messages.create(...). The -> Message return type is only a hint for editors and type checkers; at runtime the function returns whatever the SDK returned, an object with .content, .stop_reason and .usage.
The editor flags messages and tools: “list cannot be assigned to Iterable”. Is it a bug?
No, it is an editor-only complaint, not a runtime error. The SDK declares exact shapes (MessageParam, ToolParam) and a vague list[dict] cannot be proven to match. Annotate with the SDK's own types: messages: list[MessageParam], tools: list[ToolParam], and SEARCH_PUBMED_SCHEMA: ToolParam = {...}.
Ruff says: Redefinition of unused `response` from line 3.
An editor autocomplete slipped a stray from urllib import response into the top of the file. Delete the line. Then uv run ruff check . --fix for auto-fixable items and uv run ruff format . for formatting. Habit: glance at the import block after accepting an autocomplete.
Ruff says BLE001: do not catch blind exception.
The rule is right in general, because catching everything hides bugs. run_tool is a deliberate boundary: any tool failure should go back to the model as text rather than crash the run. Keep the broad catch, mark it # noqa: BLE001 with the reason, and call log.exception(...) so the full traceback is still recorded.
There is no [tool.ruff] in pyproject.toml, so where does the rule come from?
Ruff looks for config in the project, then parent folders, then a personal file (~/.config/ruff/ruff.toml). Find the active one with uv run ruff check --show-settings src/agent1/agent.py | head -20 and look for "Settings path". Put the project's own config in pyproject.toml and commit it; once a [tool.ruff] section exists, the personal file is ignored.
How do I print the total cost, not just token counts?
Add a cost_usd(model, tokens_in, tokens_out) function backed by a table of per-model prices (see chapter 8), and log the result at the end of every run, including when the step cap stops it. It is an estimate at list prices; the Console usage page is the billing truth. Prompt-caching tokens are priced differently and are not counted here.
Should the prices be read from .env?
Right instinct (prices change), wrong place. .env is for secrets and per-machine settings. Prices are not secret and are identical everywhere, so they belong in a committed data file with a source and a "last checked" date. Then a price change is a reviewable one-line diff.
How do I set a usage limit in the Anthropic Console?
Spend limits are set per organization and per Workspace, not per individual API key, and the Default Workspace cannot have one. Create a Workspace (for example agent1-dev), put the key in it, and set a small monthly limit, optionally with threshold alerts. A Workspace limit can be lower than the organization limit but never higher. Rate limits are a separate setting.
A cheaper model looks about ten times cheaper. Is that a mistake?
Check the primary source, not memory. At the time of writing (October 2026), Haiku 5.5 listed $0.10 per million input tokens and $0.50 per million output tokens for prompts up to 100K tokens (higher above that), against $1 and $5 for Haiku 4.5. Two caveats: newer models use a tokenizer that produces roughly 30% more tokens for the same text, so the real saving is nearer 7 to 8 times; and a cheaper model must be tested on your task, not assumed equal. Lesson: when a number looks wrong, go to the primary source and ask it for the whole table, not just the rows you expect.
How do I keep prompts under 100K tokens?
The threshold is per request, not per run. Prompts grow because each step resends the history. Cap tool output, clamp the model's arguments in code, keep MAX_STEPS low, and add a guard that stops when response.usage.input_tokens passes a budget (60,000 leaves headroom). Later options: count tokens before sending with the API's token-counting endpoint, and summarize or trim old tool results.
Why does the web page stream progress instead of waiting for the answer?
An agent run takes many seconds, and a silent page looks broken. The agent reports plain events through a callback, and the server streams them as newline-delimited JSON over the same POST request. It needs no extra library, and unlike Server-Sent Events it can carry a request body.
The site opens on my laptop but not on my phone.
Your laptop is probably logged in to your Tailscale network and reaches the address privately. Your phone arrives over the public internet. Check tailscale funnel status ("No serve config" means nothing is being shared; start it with --bg), allow a few minutes for public DNS the first time, and test from a device that is not on your tailnet.
Tailscale gave me a link that asks me to log in. Is something wrong?
Usually not. The first time you run tailscale funnel, it prints an admin-console link that asks you to enable Funnel (and sometimes HTTPS) for your tailnet. That link needs your login because you are the admin. Approve it, then run the command again.
